# Lab 2 复盘：高沉浸滚动网站复刻的失败原因与改进流程

> 项目：`immersive-future`  
> 参考站：<https://immersive-g.com/>  
> 复盘依据：[`final.md`](immersive-future/final.md)、[`design.md`](immersive-future/design.md)、[`motion.md`](immersive-future/motion.md)、[`assets.md`](immersive-future/assets.md) 与最终实现  
> 结论：本次实验未达到预期，但失败的核心不是某一种生成工具或 GSAP 本身，而是目标定义、技术验证、素材验收和对比反馈之间缺少明确的关卡。

## 1. 最重要的结论

原总结将失败主要归因于素材质量、3D 模型动作和 GSAP 效果，这些判断描述了最终症状，但没有定位真正的流程问题。

真正的根因是：在“到底要复刻什么”“怎样才算通过”“核心效果是否可实现”尚未确定时，项目就开始同时生产图片、视频、3D 模型、页面结构和滚动动画。后续每发现一次方向偏差，就必须返工已经完成的多个环节。

本次实验说明：

1. 高沉浸网站首先是视觉导演和运动导演问题，其次才是前端技术问题。
2. 高质量单个素材不等于高质量网页；素材必须在目标视口、排版和滚动状态中验收。
3. 复刻应优先复刻用户能感知的结果，而不是照搬参考站使用的技术。
4. “每一步更耐心”不够具体，必须把耐心转化为可判定的阶段产物、验收标准和止损条件。

## 2. 症状与根因对照

| 最终症状 | 表层解释 | 更深层根因 |
| --- | --- | --- |
| 3D 模型看起来不自然 | 生成模型质量不够 | 未在建模前确定模型的网页构图、相机角度、骨骼需求和动作轨迹 |
| 鸟不像在飞、树不像被风吹动 | 动画制作能力不足 | 将静态生成模型误当成可直接动画的角色资产，没有先验证拓扑、骨骼和可变形区域 |
| 浮雕重叠、像廉价平移 | GSAP 参数不理想 | 没有为每一章节定义唯一主视觉、进入边界、稳定区间和退出边界 |
| 文字和图片出现太晚 | ScrollTrigger 时机偏后 | 动效规范描述了时间比例，却没有用真实视口关键帧验证可读状态 |
| 每一幕被隔得很开 | 背景元素不足 | 缺少贯穿章节的共享空间母题，章节先按独立页面制作，之后才补连续背景 |
| 视频不能使用 | AI 视频质量不足 | 在静态画面、构图和运动语言尚未通过时就进入了成本更高的视频生产 |
| 不断替换模型和表现方式 | 工具效果不稳定 | 没有代表性样片和技术可行性验证，整套方案过早扩张 |
| 最终实现与设计文档不一致 | 中途调整方向 | 方向改变后没有同步更新设计、动效和素材文档，旧方案仍可能误导后续工作 |

## 3. 方案层面的问题

### 3.1 “复刻”的对象没有锁定

方案同时尝试复刻以下内容：

- 参考站的编辑式排版；
- 固定四角界面；
- 浅灰浮雕空间；
- 虚拟滚动和 WebGL 技术；
- 项目媒体的出现方式；
- 原创的“未来世界”主题和素材语言。

这些目标并不天然兼容。“未来世界”素材逐渐变成大幅写实科幻场景，而参考站的识别度主要来自低对比、局部显露、浅浮雕和大量负空间。内容主题替换最终改变了参考站最重要的视觉语法。

下一次必须先写清楚两张清单：

- **不可改变**：构图比例、文字层级、负空间、滚动方向、章节连续性、主次运动关系。
- **允许替换**：品牌、文案、对象语义、项目内容、具体纹理和声音。

### 3.2 过早锁定技术方案

在证明视觉目标之前，文档已经指定了 React、GSAP、Three.js、React Three Fiber、GLB、视频纹理和虚拟滚动。这使项目从“怎样得到正确画面”变成“怎样让这些技术都出现在页面中”。

技术选择应由视觉需求倒推：

- 只有视角、光照或形变必须实时变化时，才使用实时 3D。
- 只需要低对比空间层次时，优先考虑透明浮雕渲染、遮罩、局部缩放和轻微视差。
- 只有静态首帧和滚动节奏已通过后，才评估是否需要视频。
- GSAP 负责表达已确认的运动设计，不负责替代运动设计本身。

### 3.3 范围一次扩张过大

项目一开始规划九个章节、四个项目画面、多套 3D 模型、视频和音频，没有先验证最危险的假设：能否做出一个与参考站相近的连续滚动片段。

正确的第一版不应是完整网站，而应是一个三屏垂直切片：

```text
首屏
  ↓
宣言段
  ↓
一个项目段
```

只有这三屏在桌面、移动端、正向滚动和反向滚动中全部通过，才允许复制到剩余章节。

## 4. 素材流程的问题

### 4.1 素材脱离网页场景验收

生成图片或模型时，主要关注了对象是否精致，却没有先确认：

- 网页最终使用正面、侧面还是俯视角度；
- 对象在视口中只露出局部还是完整展示；
- 文字需要哪一侧的负空间；
- 对象轮廓在低对比条件下是否仍能识别；
- 移动端裁切后是否仍然成立；
- 动作需要整体刚体运动，还是局部骨骼、蒙皮或材质形变。

因此，植物虽然是高质量模型，但最初的渲染角度无法识别；鸟虽然具有完整外形，却没有满足飞行动画所需的结构和动作准备。

### 4.2 没有区分概念资产、生产资产和动画资产

后续必须明确三种不同交付物：

| 类型 | 目的 | 验收重点 |
| --- | --- | --- |
| 概念资产 | 确定视觉方向 | 轮廓、材质、负空间、与参考站气质是否一致 |
| 生产资产 | 进入最终页面 | 分辨率、透明通道、裁切余量、文件体积、移动端版本 |
| 动画资产 | 支持真实动作 | 拓扑、分件、骨骼、蒙皮、枢轴点、动画循环和导出兼容性 |

多视图生成能够改善几何一致性，但不能自动解决角色绑定、动作设计和网页镜头问题。

### 4.3 视频启动得太早

视频是昂贵的末端资产。只要主体造型、首帧构图或镜头语言尚未确定，视频生成就会把一个错误方向放大成更多成本。

视频生产的前置条件应为：

1. 同构静态首帧已在网页中通过；
2. 镜头运动已用低成本动画样片验证；
3. 循环点、主体一致性和裁切安全区已有明确要求；
4. 视频失败时存在可接受的静态降级版本。

## 5. 动效流程的问题

### 5.1 动效文档有参数，但缺少分镜

`motion.md` 定义了全局比例、局部进度和缓动，却没有把每个关键时间点转换成可以直接比较的画面。参数看似具体，但无法回答“这一帧为什么正确”。

下一次应先制作滚动分镜，每个章节至少包括：

1. 进入前：上一章节仍占主导；
2. 建立帧：新章节主体已经可识别；
3. 稳定帧：文字和媒体同时清晰可读；
4. 退出帧：主体局部离场，并为下一幕留下连接；
5. 反向帧：上滚时沿相同空间关系恢复。

### 5.2 缺少“稳定阅读区”验收

文字和图片出现过晚，说明实现关注了淡入过程，却没有关注用户真正能够阅读的时间。推荐将章节顶部接近视口底部时就开始建立内容，并在主体进入视口中段之前达到完整可读状态。每章至少一半的滚动区间应保持稳定阅读，不再继续大幅位移或淡入。

### 5.3 背景元素缺少所有权

多个浮雕重叠的本质是没有明确每一幕由谁占据视觉主导权。后续每个章节必须指定：

- 一个主视觉；
- 最多一个辅助轨迹或纹理；
- 上一幕元素保留到哪里；
- 下一幕元素从哪里开始接管；
- 文字区域的安全范围。

章节连续不等于让多个对象同时存在。更好的连续方式是轮廓接力、材质延续、轨迹延续或局部形态呼应。

### 5.4 “平移”被误当成空间感

整张透明图片横向或纵向穿过视口，只会暴露素材是一张平面。更合适的方式包括：

- 从画面边缘只显露对象局部；
- 用轻微尺度变化表达镜头靠近或远离；
- 围绕符合对象结构的枢轴旋转；
- 使用遮罩、景深层级和文字前后关系；
- 让轨迹线先建立方向，主体随后进入；
- 保持主体大部分时间稳定，把运动留给局部细节。

## 6. 文档与实现的问题

设计文档将 WebGL 浮雕、虚拟滚动和声音列为实现边界，动效文档又要求单一 `WorldCanvas` 和 Three.js 时间线；但最终实现已经撤掉实时 Three.js 模型，改用预渲染背景与 DOM/SVG 动效。

这不是单纯的代码变化，而是架构方向发生改变。方向改变后，以下文件都应同步标记：

- 哪些结论仍然有效；
- 哪些方案已经废弃；
- 为什么废弃；
- 当前采用什么替代方案；
- 哪些实验结果可以复用。

如果文档不更新，下一次继续工作时仍会从已经失败的假设出发。

## 7. 改进后的工作流

原工作流的问题不是顺序完全错误，而是各步骤之间没有明确的通过条件。建议改为带验收门和回退路径的流程。

```text
1. 定义复刻边界与成功标准
       ↓ Gate 1：不可改变项、允许替换项、关键参考帧已确认

2. 参考站取证与滚动分镜
       ↓ Gate 2：桌面/移动关键帧和章节接力关系已确认

3. 三屏低成本垂直切片
       ↓ Gate 3：首屏→宣言→项目段的正向/反向滚动通过

4. 代表性素材概念测试
       ↓ Gate 4：素材在网页目标视口中可识别、可裁切、不干扰文字

5. 确定技术层级
       ├─ 2D/2.5D 足够：透明渲染 + SVG + GSAP
       └─ 必须实时变化：单场景 Three.js 技术样片
       ↓ Gate 5：目标设备上的视觉和性能同时通过

6. 生产级素材制作
       ↓ Gate 6：尺寸、透明度、视角、动作、体积和降级版本通过

7. 扩展其余章节
       ↓ Gate 7：每完成一章立即进行截图与滚动对比

8. 全流程回归
       ↓
桌面 + 移动 + 快速滚动 + 反向滚动 + reduced-motion
```

## 8. 每阶段的最低验收门

### Gate 1：目标

- 用一句话描述复刻目标。
- 明确参考站中五项不可改变的体验特征。
- 明确哪些原创内容可以偏离参考。
- 决定技术实现是否属于验收目标。

### Gate 2：分镜

- 1440 × 1000 与 390 × 844 均有关键参考帧。
- 每章具有进入、稳定和退出三种状态。
- 每章只指定一个主视觉。
- 已标记文字安全区和背景对象裁切区。

### Gate 3：垂直切片

- 页面首次进入没有空白或迟到内容。
- 向下滚动运动方向一致。
- 向上滚动能够沿原路径恢复。
- 快速滚动不会跳过可读状态。
- 移动端没有横向溢出和固定 UI 遮挡。

### Gate 4：素材

- 不查看素材原图，只看网页截图时仍能识别主体。
- 素材在实际透明度下仍保留清晰轮廓。
- 正常裁切和移动端裁切都成立。
- 素材不会迫使页面通过大幅平移来展示全貌。

### Gate 5：技术

- 先证明视觉差异，再增加技术复杂度。
- 实时 3D 必须展示静态方案无法完成的价值。
- 动画资产必须经过目标动作测试，而不是只验证能否加载。
- 每种高成本技术都有静态或低性能降级路径。

### Gate 6：章节扩展

- 新章节不得破坏上一章节的退出状态。
- 同屏不出现多个争夺注意力的背景主体。
- 文字在主体完全进入前已达到可读状态。
- 截图比较和滚动录屏均通过后才能继续下一章。

## 9. 推荐的素材任务卡

以后每个素材在生成前都应包含以下字段：

```text
素材名称：
所属章节：
在视口中的位置与占比：
主体朝向：
必须保留的轮廓：
允许被裁切的区域：
文字负空间位置：
桌面视角：
移动端视角：
运动类型：整体 / 骨骼 / 材质 / 不运动
进入状态：
稳定状态：
退出状态：
降级版本：
验收截图：
```

缺少这些信息时，不应直接进入高清图片、3D 模型或视频生产。

## 10. 止损规则

为避免再次出现连续返工，建议采用以下止损条件：

1. 同一素材连续两轮无法通过网页截图验收，停止提高精度，回到构图和视角设计。
2. 模型无法完成一个代表性动作循环时，不继续制作其他同类模型。
3. 视频连续两次出现主体漂移或结构不一致，立即退回静态图或程序化局部动效。
4. 一章动效需要依赖大量特殊偏移才能成立，停止调参，重新检查 DOM 布局和分镜。
5. 新技术不能产生可见的体验提升时，不进入正式实现。
6. 参考对比只要出现主体层级、负空间或节奏方向错误，优先修正这些问题，不继续增加装饰。

## 11. 尚未确认的关键决策

本次复盘仍有五个需要在下一轮开始前明确的问题：

1. 最终目标是高相似度复刻，还是参考其语言完成原创网站？
2. 成功主要由静态视觉、滚动节奏、空间连续性还是技术还原程度决定？
3. 是否接受 2.5D 作为默认方案，将实时 3D 降为可选增强？
4. 是否同意先完成三屏垂直切片，再扩展完整页面？
5. 谁负责最终视觉验收，验收时以哪些固定截图和录屏为准？

在这五个问题得到回答前，不应开始下一轮素材生产或动效扩展。

## 12. 可复用经验

- 先验证最危险的假设，不先完成最多的页面。
- 先做分镜，再写时间线；先确认画面，再选择技术。
- 素材必须放进网页验收，不能只在生成器或 Blender 中验收。
- 动画对象必须按动作需求准备，静态模型不等于动画资产。
- 连续感来自章节之间的接力关系，不来自让所有元素同时存在。
- 截图用于判断构图，录屏用于判断节奏，两者不能互相替代。
- 正向滚动通过不代表完成，反向和快速滚动属于同等重要的验收路径。
- 每次方向变化都要同步更新设计、动效、素材和实现文档。
- 将主观评价改写成可观察的状态和明确的通过条件。
